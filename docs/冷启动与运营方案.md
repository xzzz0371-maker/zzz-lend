# ZZZ Lend — 冷启动与运营方案（Base 主网上线初期）

> 版本：v1.0 · 2026-09-03 ｜ 用途：为主网上线初期的流动性、限额、获客、监控、收入做决策参考。
> ⚠️ 本文件为运营建议，不构成财务建议；数字为估算。

## 1. 初始流动性方案

### 方案 A：项目方自有资金做市（建议先行）
- 内容：项目方以自有 USDC/USDT/DAI 存入，分散 $5–10 万（建议 USDC 4 万 / USDT 3 万 / DAI 3 万）。
- 成本：资金占用 + 机会成本（无风险利率损失）。按 $8 万占用 3 个月，4% 年化近似成本 ≈ $800。
- 风险：自身暴露于协议坏账（若发生）；但可设单资产供应上限控制。
- 可持续性：仅作为**冷启动种子**，不长期占用。
- 优点：即时可用、不依赖外部分销、可自证产品跑通。

### 方案 B：朋友/社区早期贡献者存入
- 内容：邀请 10–30 位可信贡献者各存 $1–5k，合计 $3–10 万。
- 成本：关系维护 + 激励（若有）；无直接现金成本。
- 风险：资金集中少数人；出金集中会制造利用率波动。
- 可持续性：中（帮种子期，仍依赖正式获客）。
- 优点：分散、有社区归属。

### 方案 C：流动性挖矿激励（积分/未来代币空投）
- 内容：对存款人累计积分（按美元日均 × 时间），预留未来代币空投配额。
- 成本：未来稀释（token 未发前无现金成本）；需清晰规则，避免“伪 APY”。
- 风险：激励错配（薅羊毛），需设上限（总量 + 单用户），且法律/沟通需谨慎（不承诺回报）。
- 可持续性：低→中（补贴终会退出；适合拉冷启动利用率）。
- 优点：快速上量。

### 推荐
**A+B 组合起步（$8–15 万真实资金，非激励）+ C 的积分预留作为“早期贡献者感谢”非承诺**。
理由：先有真实借款基础才能验证利率/清算；激励期短于 3 个月，避免养成补贴依赖。

## 2. 初始限额设置（风控，上线即设）

| 指标 | 建议值 | 依据 |
|---|---|---|
| 单资产供应上限 | $5 万/资产 | 防单资产集中风险（setMarketSupplyCap） |
| 单用户供应上限 | $5 万 | 防鲸鱼控利率 |
| 单用户借款上限 | $1 万 | 防大额坏账单点 |
| 总 TVL 上限 | $20 万（早期） | 控制整体敞口 |

> 注：当前合约提供 **每市场 supply cap + 每抵押 collateral cap**（`setMarketSupplyCap/setCollateralCap`）。单用户/借款上限需由前端或运营约束（合约暂未内置 per-user cap）——如要硬约束可后续加 per-user borrow cap。抵押品 collateral cap 先不设过小（防阻真实抵押）。

### 提升时间表（视数据）
| 阶段 | 时间 | 动作 |
|---|---|---|
| 第 1 周 | 上线 | 单资产供应上限 $5 万、总 TVL ≤ $20 万 |
| 第 2 周 | 观察清算/利用率/储备 | 若坏账 0、利用率 20–60%、储备充足 → 单资产上限提至 $10 万 |
| 第 1 个月 | 稳定后 | 单资产上限 $20–25 万、总 TVL $50–100 万；单用户借款上限 $5 万 |
> 提升需经治理（Timelock）逐步放开，并观察 2–3 个完整清算周期后再放大。

## 4. 上线后监控指标（对接 `services/monitor` + Telegram）

- 每日：TVL、利用率（逐市场）、借款量、存款量、净流量。
- 风险：清算次数、坏账金额、储备覆盖率、低 HF(<1.1) 仓位数、feed stale。
- 运营：用户数、活跃存款人、各 tier 实际利率。
- 告警（monitor 已实现）：可清算/低 HF/利用率>90%/储备不足/喂价失效 → Telegram push。
- 节奏：日报 + 周风险会议。

## 5. 收入预测

口径：借款人利息 × `treasuryFactor 2%`（Treasury 留存；94% 归存款人、4% 储备、2% Treasury）。

Borrow APR 近似（NORMAL + tier 溢价）取综合 ~6% 年化（利用率 50% 附近）。

| 场景 | 平均利用率 | 借款规模(占TVL) | 年化借款利率 | 月利息(估) | 月 Treasury(2%) |
|---|---|---|---|---|---|
| 保守 | 25% | TVL×25% | ~4% | | |
| | TVL $15 万 → 借 3.75 万 ×4% = $1.5k | | | | ~$30/月 |
| 中等 | 50% | TVL×50% | ~6% | | |
| | TVL $50 万 → 借 25 万 ×6% = $15k | | | | ~$300/月 |
| 乐观 | 70% | TVL×70% | ~9% | | |
| | TVL $150 万 → 借 105 万 ×9% ≈ $94.5k | | | | ~$1,890/月 |

### 盈亏平衡（覆盖开发+审计一次性成本）
假设开发/部署/审计一次性 ≈ $30–60k（含外部审计、监控、运营）：
- 中等场景（月 Treasury ~$300）→ 回本周期过长 → 说明**冷启动阶段收入不构成商业模式，价值在数据/生态占位**。
- 达到 TVL $200 万 + 利用率 50%（月利息 ≈ 200万×50%×6%/12 = $50k，Treasury $1k/月）时，可持续覆盖轻运营。
- **结论**：早期不以手续费回收为 KPI；以 TVL 健康、坏账=0、利用率的可持续增长为目标。现金流/估值故事靠“协议利用率增长”而非当前 2% 收入。

## 6. 关键待办/风险提示

1. per-user 限额非链上硬约束 → 运营层面控制（前端文案/客服），或后续加链上 per-user borrow cap。
2. 稳定币 feed 更新慢（10h+）属正常；监控阈值已按 heartbeat×N 处理，勿误报。
3. cbBTC 为 Base 生态主 BTC 抵押资产；上线前后再核验 cbBTC/USD feed 与代币流动性。
4. 上线需先跑：fork rehearsal（已做）、外部审计、多签+Timelock 收口（手册已备）。
