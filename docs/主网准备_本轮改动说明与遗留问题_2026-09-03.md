## 2. 做到位的地方（可自我评价的）
1. **D1 是“按文档语义修正”**：修复前后都有 PoC/回归测试（`AuditPocReserveOrder` 记录吸收顺序、F2 改新语义后仍守恒），不是拍脑袋删断言。
2. **每处 UI 修复都指向真实根因**：合约签名不符（withdrawCollateral）、时间型 gas 估算差（OOG）、浮点/精度（Max/科学计数）、approve 粒度、缓存刷新——均有链上/代码证据，且已部署可复测。
3. **工具链齐全**：Slither 0（39 合约/102 检测器）、fuzz5000、状态机不变式 4/4、覆盖率报告、合约 ≤ EIP-170（LendingPool ~20.6KB）、格式/lint。
4. **测试反映“新语义”而不是“保绿”**：D1 顺序变更后显式更新了受影响断言，并新增 peg/全额还款回归。
5. 演示/迁移过程有备份与回滚点（旧池保留、json 备份），部署失败有重试与预演。

## 3. 仍存在的问题 / 不确定性（重要，请勿跳过）
### 3.1 协议/代码层面
1. **D1 顺序选择仍需产品/治理签字**：我们定为“物理→账面→treasury→存款人”，即存款人最后兜底。这意味着**坏账先吃储备与 treasury**。需确认：treasury 是否也愿意承担（它原本是“收益归集”，被坏账吃掉会少收）；以及极端时（损失 > 储备+treasury）存款人仍受损的阈值是否可接受。**这是策略决策，代码按新策略实现，但需治理确认。**
2. **“全额还款一次清零”语义变化**：`repay ≥ 债务` 时整笔清零；部分还款仍走 floor 取整。需确认无“借一小笔后故意不 accrue 再全额还”的歧义——accrue 在 repay 内先执行，债务含利息，无套利窗口；但该语义与 Aave 类“还多少扣多少”不同，**请在文档中明示**。
3. **SafeERC20 ≠ 支持所有 token**：只解决“无返回值”。**fee-on-transfer / rebasing / 非标准 ERC20 仍不被支持**（实收≠记账）。主网必须“仅接入标准 ERC20”白名单，并人工核验每个目标 token 的转账/精度。
4. **不可升级（无 proxy）**：任何未来 bug/策略调整 = 整组重部署 + 旧池资产迁移问题。主网上**强烈建议先评估代理/升级方案或接受“发版即永久”**。
5. **Oracle 中断对“有债用户”的降险/清算发现仍受影响**：抵押品取回需读价；feed stale 会临时锁（M2 缓解仍待做：如多价源、降级路径、预警）。当前 Sepolia 演示靠 Switchable 可设价绕开，**这不是主网方案**。
6. **用户事件已移除（EIP-170）**：清算/仓位监控只能靠轮询视图；主网需 Subgraph/索引（仍未建）。
7. **坏账前抢先提款无延迟**（front-run / bank-run）：known trade-off；主网建议提款队列/锁窗或正式公示承担模型（仍未做）。

### 3.2 测试覆盖不确定性
8. **fuzz 覆盖面低**：绝大多数用例是确定性状态测试；新增的随机性主要来自 invariant（4 个）。缺针对 repay/liquidate 金额的定向 fuzz 属性。
9. **参数极端矩阵**（closeFactor=0/100、bonus=0/50、reserve=0/10%、多档价格组合）多为人工推演，缺自动化矩阵用例（部分写入 §报告）。
10. **USDT/DAI peg 只补了基本隔离**；未做“同区块多币同时大幅波动 + 清算+坏账”全组合压力。
11. **wstETH 真实兑换率**：当前按 wstETH/USD 直喂（Mock 固定价）。“wstETH/ETH×ETH/USD”合成、双 feed stale/deviation 组合、兑换率突变对清算数学的影响**未在测试网真实验证**——主网上必须用真实 feed 再跑 dress rehearsal。
12. **Sepolia 演示的 USDC/USD 真实 feed 常 stale**：演示全部走可设价，掩盖了 feed 可用性问题；主网 feed 健康度是上线前必检项。

### 3.3 工程/流程不确定性
13. **无外部第三方审计**：当前结论只基于自审（Slither + 人工 + 测试）。自审可能有盲区，**不建议凭自审结论上主网**。
14. **钱包/智能账户兼容**：测试中你的 Smart Account（Rhinestone 类模块，`0xdb9B…`）多次 underflow 导致交互失败——与 ZZZ 无关，但提示 **UI 对 EOA/SA 的适配与错误提示仍需打磨**（如 SA 的 pending/估计失败应给可读反馈）。
15. **gas 估算波动**：我们给池写交易设 1M 上限缓解 OOG，但**依赖钱包尊重传入 gas**；不同钱包/账户（尤其 SA）行为未逐一验证。
16. **Cloudflare 部署时机**：推送后自动/手动部署存在数分钟空窗与缓存（需硬刷新），不是代码问题但影响验收节奏。
17. **旧池资产**：历次归档池（`0x8c38…`、`0xc666…` 等）仍持有历史测试资产；若被误用会混淆。建议要么清空、要么明确标注“仅存档”。

### 3.4 经济参数不确定性
18. 三段利率/储备 3%/分成 94/4/2 是**按需求设定的初值**；真实利用率分布下的清算频率、reserve 充分性、激励一致性**没有真实流量验证**。主网前应做参数风控测算与初始限额（单资产供应/抵押上限）。
